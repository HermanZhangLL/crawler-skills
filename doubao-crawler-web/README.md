# doubao-crawler-web

`doubao-crawler-web` 是一个 **豆包（Doubao）网页端 / Android App AI 搜索重复采样与 GEO 概率分析 Skill**。它通过 OpenCLI Browser Bridge 自动操作已登录的豆包网页会话完成提问 → 回答稳定判定 → 创建 thread 分享链接 → 解析公开快照结构化数据 → 统一存储 → 概率分析报告的完整链路；另支持 Android/Appium 低频 UI 采集后端。

它不是通用网站爬虫，也不调用豆包 API。Android 后端不绕过登录、验证码、风控、隐藏 API 或 App 网络流量。

版本记录：[CHANGELOG.md](CHANGELOG.md)

## 核心链路

```text
1. 自动化操作软件    OpenCLI 驱动已登录的豆包网页会话（回答完成以文本稳定读取判定，
                     非固定等待；--completion-timeout 600s / --poll 8s / --stable-reads 2）
2. 收集链接          捕获 thread 公开分享链接（www.doubao.com/thread/<id>）
3. 链接数据获取      解析公开 thread 快照：全量消息列表、搜索关键词块、引用卡片全字段、
                     suggest_questions、brief、时间信息；敏感身份字段落盘前脱敏
4. 统一存储          doubao-crawl.json 规范数据集 + raw/*.json + logs/*.log +
                     question-links.csv / full-sample-data.csv / share-links.xlsx +
                     field-maps/*.html（每题一份数据字段地图）
5. 分析与报告        实体识别 + 同类型竞品对比 → Markdown/Excel/HTML 四件套；
                     另可出 DeepSeek 样式 GEO 基线测评报告（analyze_geo_baseline.py）
```

## 技术路线

- **网页端 + 移动端双后端**：网页端走 OpenCLI 浏览器自动化；移动端走 Android/Appium UiAutomator2 低频 UI 采集，两者产出**同一 canonical `doubao-crawl.json` 结构**，分析器统一处理。
- **链接即证据**：thread 分享链接是结构化数据的权威来源——回答完成后捕获公开 thread 并解析快照；链接捕获/解析失败分别记为 `thread_link_failed`/`thread_parse_failed` 并计为失败样本，可 `--retry`/`--resume`/`--repair-shares` 补救。
- **双通道采集**：除实时提问外，可直接解析已有 thread 链接（`--thread-url`/`--thread-urls`，无需登录）；`--defer-parse` + `--capture-threads` 支持"先全部提问、后批量取快照"两阶段。
- **项目归置**：`--project <名称>` 把每个新会话自动移入豆包"项目"（对标元宝分组），移动失败不判定样本失败。
- **风控熔断与自适应延迟**：连续 `answer_incomplete` 自动熔断冷却；按最近 10 题成功率动态调延迟（≥90% 缩短至 15%，<70% 加倍）。
- **证据优先**：每题保留 raw JSON、日志、可见 URL/引用行；概率指标均为重复采样估计。

## 预设值与取舍

默认值以"**采得回来、链接可信、不触发风控**"为第一目标；效率让位于稳定性。

| 预设项 | 默认值 | 取舍说明 | 如何调整 |
|---|---|---|---|
| 每题次数 | `1` | 豆包回答较慢，重复采样成本高 | `--repeat <n>` |
| 题间间隔 | 随机 `60-100 秒` | 压低风控风险 | `--safe-random-delay`（5-20 分钟）、`--moderate-delay`（60-180 秒） |
| 完成判定 | 文本稳定读取（2 次稳定） | 非固定等待，避免答得慢被误判 | `--completion-timeout`（600s）、`--poll-interval-seconds`（8s）、`--stable-reads`（2） |
| 熔断器 | 连续 3 次 `answer_incomplete` → 冷却 10 分钟 | 防账号风控时空转 | v1.2.0 起内置；冷却后试探 2 题 |
| 自适应延迟 | 按近 10 题成功率动态 | 快时更快（最低 5-10s）、慢时加倍 | 内置；固定延迟用 `--delay-*` |
| 问答模式 | `--doubao-mode 快速` | 豆包无 Vision/独立深度思考开关（不当作可选项） | `--doubao-mode` |
| 创建分享链接 | 开启 | thread 链接是结构化数据权威来源 | `--no-create-share` 关闭 |
| 导出表格 | Excel + 字段地图默认开 | 增加少量导出耗时 | `--no-excel`、`--no-field-maps` |
| 项目归置 | 关闭 | 开启需已有豆包"项目" | `--project <名称>` 或 `DOUBAO_PROJECT` |
| 失败重试 | 不自动 | 失败样本显式补 | `--retry <n>`、`--resume`、`--repair-shares` |
| 两阶段取快照 | 关闭 | 先问完再批量取快照，减少占用 | `--defer-parse` + `--capture-threads` |
## Stage 1: Batch Crawl

Default web backend:

Create `questions.txt` with one question per line, then run:

```bash
node scripts/doubao_batch_crawl.mjs \
  --questions questions.txt \
  --repeat 1 \
  --doubao-mode 快速 \
  --profile <opencli-profile> \
  --target-entity "新东方" \
  --target-aliases "新东方前途出国,前途出国" \
  --entity-type company \
  --out-dir runs/doubao-study-abroad
```

Outputs:

- `runs/doubao-study-abroad/doubao-crawl.json`
- `runs/doubao-study-abroad/question-links.csv` (run_id/sample_id/question/thread link/timestamps per sample)
- `runs/doubao-study-abroad/full-sample-data.csv` (UTF-8 BOM; one row per sample with the full parsed record: answer, brief, suggest questions, search queries/blocks, references, message list, timing, raw/log paths)
- `runs/doubao-study-abroad/share-links.xlsx` (question -> share link workbook with 分享链接 and 按问题汇总 sheets; generated by default, pass `--no-excel` to skip)
- `runs/doubao-study-abroad/field-maps/<question_id>-data-map.html` (one data field map per question, from the first valid repeat; generated by default, pass `--no-field-maps` to skip)
- `runs/doubao-study-abroad/raw/*.json`
- `runs/doubao-study-abroad/logs/*.log`

Before a real run, confirm all 10 items with the user: question set, per-question repeat count, target entity/entity type/competitor alias table, inter-question delay, answer mode, create public share links, export tables + share-link Excel, field maps, browser profile, and output dir; see `references/pre-run-confirmation.md`. Unanswered items use defaults: repeat=1, random 60-100s delay, quick mode, create share on, Excel on, field maps on, current profile, auto timestamped output dir, and no target means exploratory analysis.

Use `--dry-run` to verify the plan without opening Doubao; dry-run does not require the crawler script to exist. The default inter-question delay is random 60-100 seconds; `--safe-random-delay` (5-20 minutes) and `--moderate-delay` (60-180 seconds) are optional overrides. If the OpenCLI Doubao adapter can ask/read but cannot reliably open a fresh conversation, pass `--no-new` and label the run because samples may share conversation context.

The default web flow operates the browser to ask (`--completion-mode browser`): it opens a Doubao conversation, sends the prompt, polls the page until the answer text is stable, captures the thread share link, then parses the public snapshot. It no longer relies on a fixed per-question wait; completion is judged by stable reads (`--completion-timeout`, default 600s; `--poll-interval-seconds`, default 8s; `--stable-reads`, default 2). Samples that do not finish within the cap are marked `failure_reason=answer_incomplete`; samples whose public share link cannot be captured or parsed are marked `thread_link_failed` / `thread_parse_failed` and count as failed. Failed samples can be retried with `--retry <n>`, `--resume`, or `--repair-shares`.

### Web 双通道：thread 分享链接

Besides asking fresh questions, the skill can parse an existing Doubao share link without opencli or login:

```bash
node scripts/doubao_browser_crawl.mjs \
  --thread-url https://www.doubao.com/thread/<share_id> \
  --out raw/thread-sample.json

node scripts/doubao_batch_crawl.mjs \
  --thread-urls thread-links.txt \
  --out-dir runs/doubao-threads
```

`thread-links.txt` contains one share URL or share_id per line. Each parsed thread stores structured evidence: share metadata, full message list, search query blocks, all reference-card fields, `suggest_questions`, `brief`, timing (`asked_at/completed_at/question_message_time/share_time`), and completion flags. The thread snapshot does not contain the answer mode, so `doubao_mode` is recorded from the browser asking step when the question is submitted. Sensitive identity fields are redacted before writing. Every sample is also exported to `full-sample-data.csv`, and one per-question data field map is written to `field-maps/<question_id>-data-map.html` by default (`--no-field-maps` disables the HTML).

Two-phase fallback for ask-mode runs that collected conversation links but not snapshots:

```bash
node scripts/doubao_batch_crawl.mjs --capture-threads --out-dir runs/<existing-run>
```

`--defer-parse` asks all questions first and leaves `pending_thread_capture=true`; the `--capture-threads` pass then fetches structured snapshots without re-asking.

Android/Appium mobile backend:

```bash
python3 -m pip install -r requirements-mobile.txt
appium driver install uiautomator2
appium
```

```bash
python3 scripts/doubao_mobile_crawl.py preflight \
  --device emulator-5554 \
  --app-package com.larus.nova \
  --server http://127.0.0.1:4723
```

```bash
python3 scripts/doubao_mobile_crawl.py batch \
  --questions questions.txt \
  --repeat 1 \
  --device emulator-5554 \
  --app-package com.larus.nova \
  --input-resource-id com.larus.nova:id/input_text \
  --target-entity "新东方" \
  --entity-type company \
  --out-dir runs/mobile-doubao-poc \
  --delay-min-minutes 5 \
  --delay-max-minutes 20
```

Mobile outputs use the same canonical `doubao-crawl.json` shape as the web backend, plus `raw/*.json`, `logs/*.log`, `screenshots/*`, and `xml/*`. Mobile records also keep `timing.asked_at/completed_at`, `suggest_questions`, and `answer.brief` (empty placeholder when the app does not expose a brief). The analyzer treats mobile answers and visible reference rows as compatible evidence.

When Doubao exposes `搜索 N 个关键词，参考 M 篇资料`, the mobile backend expands that block, stores the visible search-material list in `result.mobile_search_materials`, and marks each material as cited or uncited with `citation_count`. Add `--recover-material-links` for controlled runs where the script should tap each visible material row to recover URL/detail evidence. Add `--skip-search-materials` to disable this expanded-material stage.

Use a fresh app conversation for each sample when repeated answers must be isolated:

```bash
python3 scripts/doubao_mobile_crawl.py batch \
  --questions questions.txt \
  --repeat 5 \
  --device emulator-5554 \
  --app-package com.larus.nova \
  --server http://127.0.0.1:4725 \
  --fresh-chat \
  --require-fresh-chat \
  --delay-min-seconds 0 \
  --delay-max-seconds 30 \
  --out-dir runs/mobile-doubao-fresh
```

`--fresh-chat` taps the visible Doubao "创建新对话" control before sending each prompt. `--require-fresh-chat` fails a sample instead of accidentally continuing in an old conversation when that control cannot be found.

## Stage 2: Analyze And Render

Standard input fields:

```text
1. 关键词：出国留学公司推荐、出国留学机构哪家好
2. 轮询次数：每个关键词查询 5 次
3. 目标实体：新东方
4. 实体类型：公司
```

Optional `brands.txt` can provide reviewed aliases and competitors:

```text
新东方|新东方前途出国|前途出国
启德教育|启德留学|启德
新通教育
指南者留学|指南者
```

Run:

```bash
python3 scripts/analyze_doubao_results.py \
  runs/doubao-study-abroad/doubao-crawl.json \
  --target-entity "新东方" \
  --target-aliases "新东方前途出国,前途出国" \
  --entity-type company \
  --brands-file brands.txt \
  --out-dir runs/doubao-study-abroad/report
```

Outputs:

- `runs/doubao-study-abroad/report/summary.json`
- `runs/doubao-study-abroad/report/structured-data.md`
- `runs/doubao-study-abroad/report/structured-data.xlsx`
- `runs/doubao-study-abroad/report/report.html`

The standard diagnosis report requires `--target-entity` and `--entity-type`. Entity type accepts `person/人`, `company/公司`, or `product/产品`. Target matching uses contains logic plus aliases, so target `新东方` can consolidate `新东方前途出国` and `前途出国` into the same target row. Short Latin aliases such as `AI` or `GEO` only match standalone tokens to avoid accidental matches inside longer names. Competitors are limited to the same entity type as the target. The report compares the target and competitors by mention rate, average mentions per valid answer, Top 1 / Top 3 / Top 5 probability, average rank, dominant sentiment, negative share, and source mentions.

If no target entity is supplied, the analyzer still produces an exploratory report: it shows collection coverage, compatible references, mobile evidence, and inferred same-type candidates, but it does not claim target-vs-competitor metrics.

`structured-data.md` and `structured-data.xlsx` contain the same cleaned tables for overview fields, question coverage, mobile evidence, entity metrics, source/channel data, title features, and output file paths. The HTML defaults to Simplified Chinese and includes an English summary toggle, Chinese source display names when domains can be mapped, clickable repeated URLs/titles with unique compact URL labels, mobile search-material evidence with cited/uncited counts, normalized target-vs-best-3 radar scoring when a target exists, click-to-reveal bubble benchmarking, title intent analysis, compact domain treemap, and GEO recommendations with priority charts, conservative trend projections, and concrete methods. Doubao source analysis is limited to visible markdown links, bare URLs, or compatible reference rows exposed by the crawler output.

Exploratory legacy mode still supports `--target-kind auto/person/company/product/mixed`, but final reports should use the standard target fields above.

## GEO 基线测评报告（DeepSeek 样式）

在现有四件套之外，可生成一份参照 DeepSeek 基线测评报告形式的品牌 GEO 基线测评报告（总览 → 逐题分析 → 信源分析 → 推荐追问 → 关键发现 → 行动建议），并利用豆包结构化字段增强：搜索关键词、引用全字段、brief 摘要、时间信息、泛需求 vs 直接提问、信源覆盖矩阵。

```bash
python3 scripts/analyze_geo_baseline.py runs/xxx/doubao-crawl.json \
  --target-entity "和光书苑" \
  --entity-type product \
  --out-dir <输出目录> \
  --out-file "和光书苑_豆包Web基线测评报告.html"
```

输出自包含 HTML 与同名 Markdown；支持 `--merge-runs` 合并多次测评。完整方案与实现细节见 `references/geo-baseline-report-plan.md`。
