# 豆包 Web 采集前确认清单

每次正式测评开始前，按以下 11 项向用户确认。用户不回答时使用默认值；问题清单没有默认值，未提供则不开始采集。

## 1. 问题集（必填，无默认值）

格式：文本文件（每行一个问题）、JSON 数组，或直接粘贴到对话中。

```text
保定市区买小高层，推荐个新交付或即将交付的小区
保定即将交付的小高层楼盘有哪些
```

```json
[{"id":"q01","question":"保定市区买小高层，推荐个新交付或即将交付的小区","repeat":1}]
```

- 未提供问题集：不开始采集，先等用户给题。
- JSON 对象支持对单个问题写 `"repeat":5`、`"mode":"专家"` 覆盖全局设置。

## 2. 每个问题提问次数

- 默认值：1（`--repeat 1`）。
- 范围：1-50。
- 提问话术示例："每个问题提问几次？默认 1 次，范围 1-50；也可以只对部分题目指定次数。"

## 3. 目标实体、实体类型、竞品/别名表

提问时给出示例，方便用户按格式填写：

- 目标实体：和光书苑
- 实体类型：`product`（可选 `person` / `company` / `product`，或 `人` / `公司` / `产品`）
- 目标别名：`和光书苑,深圳园·和光书苑`
- 竞品/别名表（每行一个品牌，同一行用 `|` 分隔别名）：

```text
东湖尚品|东湖尚品·云境苑
绿城·保定蘭园|保定蘭园
泉尚悦湖
```

默认值：

- 未提供目标实体/实体类型：运行探索性分析，不生成目标对比指标，从回答推断竞品并标记为启发式结果。
- 未提供别名/竞品：分析阶段自动从回答中推断同类型竞品，并在报告中标注为启发式推断结果。

## 4. 题间采集间隔

- 默认值：随机 60-100 秒（等价 `--delay-min-ms 60000 --delay-max-ms 100000`）。
- 可选更安全模式：`--safe-random-delay`，随机 5-20 分钟。
- 可选自定义：`--delay-min-minutes <n> --delay-max-minutes <n>`。
- 仅测试可缩短：`--delay-ms <ms>`。
- 说明：这是"题与题之间"的延时，不是单题等待时间；单题是否回答完毕由稳定轮询判定，见下。

## 5. 采集模式

- 可选值：`快速`（默认）、`专家`、`工作任务 Turbo`、`工作任务 Pro`；也可以写 `quick` / `expert` / `work-turbo` / `work-pro`。
- 浏览器自动提问时会打开豆包输入区的模式菜单并选择对应模式；`options.doubao_mode` 会写入原始数据和两张 CSV。
- 豆包网页端当前不提供 Vision 模式和独立的"深度思考"开关；DeepSeek 的 Vision / 深度思考配置在豆包没有对应能力，不在确认清单中启用。
- 每次测评默认使用用户确认的模式；问题清单 JSON 对象中可对单个问题写 `"mode":"专家"` 覆盖全局设置。

## 5.5 是否把新会话归入指定“项目”

- 默认：不归入（`--project` 未设置）。
- 需要时：用户提供豆包网页端已创建好的项目名（例如“20260901 和光书苑全意图-第1轮”），采集时传 `--project <项目名>` 或设 `DOUBAO_PROJECT` 环境变量。
- 行为：每个样本在“提问 → 回答 → 采集分享链接”完成后，通过侧边栏 UI 自动化把该会话移入指定项目；结果记录在样本 `project_move` 字段。
- 注意：项目必须已存在；采集器不自动创建项目。移动失败不把样本判为失败，但保留错误供事后处理。

## 6. 是否创建公开分享链接

- 默认：创建（`--create-share` 默认开启）。浏览器提问、回答稳定后捕获 thread 分享链接，并从公开分享快照解析全量数据（正文、brief、推荐问题、搜索块、引用、消息列表等）。
- 关闭：`--no-create-share`。只保留回答文本与可见引用，成功口径不要求分享链接。
- 说明：分享链接是公开的；链接创建失败或快照取不到数据时，样本标记为失败，不算成功。

## 7. 是否导出数据表和"问题→分享链接" Excel

- 默认：导出。
- CSV 始终导出：`question-links.csv`（问题、轮次、分享链接、提问时间）、`full-sample-data.csv`（每样本全量字段）。
- Excel：`share-links.xlsx` 默认生成，包含"分享链接"明细和"按问题汇总"两个工作表；`--no-excel` 可跳过。
- 说明：字段地图是第 8 项，不归本项管。

## 8. 是否生成每个问题的数据字段地图

- 默认：生成。
- 每个问题生成一份 `field-maps/<question_id>-data-map.html`；同一问题无论提问多少次，只取第一个有效样本生成一份。
- 关闭：`--no-field-maps`。

## 9. 浏览器采集 profile

- 默认：使用当前已登录的采集 profile（OpenCLI Browser Bridge 连接的那个）。
- 如果有多个 profile，请告知要使用的那个，采集命令转成 `--profile <name>`。

## 10. 输出目录

- 默认：自动生成 `runs/<时间戳>` 目录。
- 用户可指定 `--out-dir <dir>`。
- 若目标目录已存在旧测评（含 `doubao-crawl.json`），自动升级为 `-v2`、`-v3` 版本目录，不覆盖旧版本。

## 质量与边界（每次测评都执行）

- 一次只跑一个采集任务，不并行多个，避免浏览器互相干扰。
- 一次采集尽量固定同一个账号；切换账号可能导致之前创建的分享链接失效。
- 分享链接必须保证公开可访问；链接创建失败或取不到数据 -> 该样本标记失败，不能算成功。
- 采集过程中不删除、不覆盖已有历史版本；需要升级时使用版本号目录区分。

## 转换示例

```bash
node scripts/doubao_batch_crawl.mjs \
  --questions questions.txt \
  --repeat 1 \
  --doubao-mode 快速 \
  --profile <opencli-profile> \
  --target-entity "和光书苑" \
  --target-aliases "和光书苑,深圳园·和光书苑" \
  --entity-type product \
  --out-dir runs/doubao-20260806
```

默认已开启：随机 60-100 秒题间延时、创建公开分享链接、`share-links.xlsx`、每问题字段地图。竞品/别名表保存为 `brands.txt`，在第二阶段分析时传入：

```bash
python3 scripts/analyze_doubao_results.py runs/doubao-20260806/doubao-crawl.json \
  --target-entity "和光书苑" \
  --target-aliases "和光书苑,深圳园·和光书苑" \
  --entity-type product \
  --brands-file brands.txt \
  --out-dir runs/doubao-20260806/report
```

## 默认 web 采集链路

- 采集模式：浏览器自动打开模式菜单并按确认结果选择（默认快速），记录 `doubao_mode`。
- 提问方式：浏览器操作提问，默认 `--completion-mode browser`。
- 回答完成判定：轮询页面文本，文本包含提问、长度足够，且连续 `--stable-reads`（默认 2）次一致，不依赖固定等待。
- 链接采集：判定回答稳定后，立即从页面分享菜单捕获 thread 链接，再解析公开分享快照；无链接或解析失败 -> `thread_link_failed` / `thread_parse_failed`，样本 `ok=false`。
- 题间延时：默认随机 60-100 秒；可覆盖为 `--safe-random-delay`、自定义随机区间或测试用 `--delay-ms`。
- 回答超时上限：`--completion-timeout` 默认 600 秒；超时样本标记 `answer_incomplete`，可用 `--retry`、`--resume` 或 `--repair-shares` 处理。

## 移动端 App 采集同步

- 原始数据同样记录 `timing.asked_at / completed_at`（提问前与稳定判定时刻）。
- `answer.brief` 保留为空占位字段（App 不暴露 brief 摘要）。
- `suggest_questions` 从可见文本尾部解析"推荐查看问题"（含 `推荐问题 / 大家还在问` 等场景），存入原始数据并进入正式指标。
